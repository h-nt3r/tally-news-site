Run your own

This is an open-source news aggregator, made to be copied. The list of outlets, how they are labeled and how stories are ordered all live in plain files you can read and change.

Follow people and other copies

In the workbench’s Manage page (or groups.py add for a group), paste any of these as a source and it becomes an ordinary feed:

  • a Mastodon account: @name@instance.social or the address of its profile page;
  • a Mastodon hashtag: #tag@instance.social;
  • a Bluesky account: bsky.app/profile/handle;
  • another copy of this project: its feed.xml, breaking.xml or blindspots.xml address. A group can import another group’s sources.opml the same way to borrow its source list.

Posts have no headline of their own, so their first words are used. A post is one person’s words, not a news report: give these sources a side and a type that say so, and expect them to group loosely with articles. Walled platforms with no open route (Instagram, TikTok, Facebook, X) cannot be followed this way.

Put it on the web

The page is plain files, so any static host works. publish.py sends the finished site/ folder to a Git repository served by GitHub Pages. It stays off until you create a file named publish.local.toml (it is not saved to git) with repo, optionally branch, min_minutes (at most one push that often; default 10) and exclude_thumbnails. After each build it keeps a single commit, force-pushes it, and prints one line to the build log. Only the finished pages are sent: never your history, cache, logs or settings. Preview frames and video thumbnails are small copies of other people’s images; set exclude_thumbnails = true to leave them out. The computer that builds the site has to be on for the public copy to stay current; when it is not, the page’s own “updated” time shows how old it is.

Run it on your computer

It was built and tested on a Mac. You need Python 3.11 or newer.

  1. Open a terminal in the project folder and set it up once: 
    python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
  2. Build the news and start the site: 
    ./run.sh
  3. Open http://localhost:8765 in your browser.

To read it on your phone while on the same Wi-Fi, run ./run.sh --lan. It prints an address to open on the phone. Anyone on that Wi-Fi can open the page while it runs, so skip this on public networks.

Keep it up to date

The site only shows the news as of its last build. On a Mac, ./schedule.sh install sets up two background jobs: one rebuilds every 5 minutes and one keeps the page available. Each feed is asked whether it has changed since the last look (ETag and Last-Modified) and compressed copies are accepted, so an unchanged feed costs the outlet one tiny reply. The page is published first; any new summaries are written afterwards and the front page is refreshed. Add --lan to reach it from a phone on the same Wi-Fi. ./schedule.sh status shows whether it is running and how old the page is, and ./schedule.sh uninstall removes it.

On Linux, or any machine with cron, run the build on a schedule yourself and serve the site/ folder with any web server:

*/20 * * * * cd /path/to/project && .venv/bin/python build.py

A build that finds almost nothing is discarded, so the last good page stays. An open page checks for newer builds every few minutes and offers a refresh; it never reorders by itself.

Run one for your group

A mutual aid network, union local, chapter or neighborhood group can run its own copy with its own name and its own outlets, as an alternative to getting news through social media. A group is one plain file. No account, nothing sent anywhere.

.venv/bin/python groups.py new "Eastside Mutual Aid"
.venv/bin/python groups.py add eastside-mutual-aid https://your-local-paper.org
./group.sh eastside-mutual-aid

The first command makes groups/eastside-mutual-aid/group.toml. The second finds the feed on a pasted website and adds it; you choose its label (--lean left|center|right) and topic. The third builds the page and serves it on its own port. Add --empty to the first command to start from only your own outlets, and leave it off to start from the full default list and remove what you don't want. Keeping other outlets in the mix is deliberate: your group sees what everyone else is saying, or not saying, and can hide any outlet it chooses.

Local outlets rarely cover the same story, so a group's page also lists headlines reported by only one outlet. The list of groups, their ports and their settings are in groups.py list.

Follow a page with no feed

Many local sources (a council news page, a union's announcements) have no feed. A group can watch the page instead, and each new link that appears becomes an item:

.venv/bin/python groups.py add-page eastside-mutual-aid https://example.gov/council/news --link-contains /news/

It shows the links it finds so you can check it picked headlines and not menus; --link-contains and --min-words narrow it down. It is polite: it honors robots.txt and looks at a page at most every 30 minutes. See how it works and its limits.

Choose your own sources

Every outlet is a short block in config/sources.toml. Copy one, change the name and web address, set its label, and run ./run.sh again.

[[feeds]]
name = "Example Daily"
url = "https://example.com/rss.xml"
lean = "center"     # left, center or right
type = "commercial"  # optional: wire, public, state, nonprofit or commercial (leave it out if unsure)
topic = "us"        # us, world or tech

The Sources and Settings pages only switch things on or off among outlets already in the build. To add a new outlet, edit the file and rebuild. That is what a fork is for.

Make it your own: the workbench

Run ./workbench.sh and open http://localhost:8766. It is a private copy of this page for this computer only, with a Manage sources page where you can remove outlets you never want to see, add new ones by pasting a website, a feed address or a YouTube channel, and change a side label you disagree with. Your changes are saved in workbench/changes.toml on top of the default list, so you can always press Reset to default to get the full picture back. The public page never changes. Add --lan (./workbench.sh --lan) to also show a read-only copy on your phone over the same Wi-Fi.

Follow accounts for clips

Add accounts on open platforms under [[social]] in config/sources.toml. They show up under “Clips and posts”, newest first, and never count toward the left, center and right numbers.

[[social]]
name = "Bellingcat"
platform = "bluesky"      # bluesky, mastodon or reddit
handle = "bellingcat.com" # mastodon: "@user@instance.social" or "#tag@instance.social"; reddit: "r/worldnews"
# kind = "all"            # default is video posts only

Clips play in this site’s own player, straight from the public file. To keep each clip’s preview frame off this site (for example on a public copy, where hosting other people’s images may matter), set clip_thumbnails = false under [settings]; cards then show a plain dark tile.

To open Reddit or YouTube links through an open-source privacy front end, add an [open_with] section (examples are in the file). TikTok and Instagram have no open feed and are not scraped.

How stories are ordered

Outlets reporting the same event are grouped by comparing the words in their headlines and summaries. Groups are ranked by how many different outlets are in them, then by how recent they are. Nothing about you, your clicks or what is popular changes that order.

The popularity labels (shares on Mastodon, trends on Bluesky, points on Hacker News, video views) are shown beside stories for information only. Each one links to the platform: Bluesky opens its feed for that topic, Hacker News opens the discussion, and Mastodon opens its list of trending links (it has no page for a single article, and the list changes through the day). Those audiences are small and tech-minded, so a story with no label is not unimportant.

How labels are set

Left, center and right are one maintainer’s judgment and are not facts. The outlet type (how it is funded or owned) is also a classification by the maintainer, set only where it is well documented. They are in config/sources.toml, and the Sources page lists every one. If you disagree, change it in your copy.

What is in the folder

config/
the list of outlets and a few settings
build.py
fetches the news, groups stories, writes the pages
archive.py
remembers every headline and gives each story a lasting id
analytics.py
works out the timing facts, counts and the data file
template/
how the pages look and behave
run.sh
builds and serves the site by hand
schedule.sh
keeps the site current on a Mac

How this works: stories are ordered by how many different outlets covered them, then by recency. Nothing learns from you. Left, center and right are one maintainer's judgment, not facts (every source and its label).

Numbers here are counts and timings you could recount by hand (how each is made). Archive · Data as JSON. Popularity labels link to the platform they come from.
